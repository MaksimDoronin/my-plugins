Проверь вёрстку фронтенда через Playwright.

## Аргументы

- `$0` — конкретная страница для проверки (`login`, `register`, `dashboard`, `categories`).  
  Если аргумент не передан — проверить все ключевые страницы.

## Шаг 0 — убедиться, что dev-сервер запущен

Проверь, слушает ли порт 3000:

```bash
lsof -i :3000 | grep LISTEN
```

Если порт не занят — выведи предупреждение и попроси пользователя запустить `npm run dev:frontend`, затем прерви выполнение.

## Шаг 1 — определить страницы для проверки

| Ключ        | URL                                    |
|-------------|----------------------------------------|
| `login`     | `http://localhost:3000/login`          |
| `register`  | `http://localhost:3000/register`       |
| `dashboard` | `http://localhost:3000/` (main экран)  |
| `categories`| `http://localhost:3000/categories`     |

Если `$0` передан — проверить только соответствующую страницу. Иначе — все четыре.

## Шаг 2 — для каждой страницы выполнить следующий чеклист

### 2.1 Desktop (1280×800)

1. Навигировать на страницу через `mcp__playwright__browser_navigate`.
2. Дождаться загрузки через `mcp__playwright__browser_wait_for` (selector: `body`, state: `visible`).
3. Сделать скриншот через `mcp__playwright__browser_take_screenshot`.
4. Снять snapshot DOM через `mcp__playwright__browser_snapshot` — проверить:
   - Нет элементов с нулевой высотой/шириной там, где не ожидается.
   - Заголовки и основные блоки присутствуют.
   - Кнопки и поля ввода доступны (не скрыты overflow/opacity: 0).
5. Получить консольные сообщения через `mcp__playwright__browser_console_messages` — выделить `error` и `warning`.

### 2.2 Mobile (390×844)

1. Изменить размер через `mcp__playwright__browser_resize` (width: 390, height: 844).
2. Навигировать заново / обновить страницу.
3. Сделать скриншот.
4. Снять snapshot — проверить адаптивность: меню, контент, кнопки.
5. Вернуть размер обратно (1280×800) для следующей страницы.

## Шаг 3 — критерии проверки вёрстки

Для каждой страницы сообщать о следующих проблемах:

| Проблема | Как обнаружить |
|----------|----------------|
| Контент выходит за границы экрана (overflow) | snapshot / скриншот |
| Текст обрезан или перекрыт другим элементом | snapshot |
| Кнопки/поля недоступны или не видны | snapshot + aria-roles |
| Сломана адаптивная вёрстка на мобильном | скриншот 390px |
| JS-ошибки в консоли | `console_messages` с типом `error` |
| Пустая страница (нет контента) | snapshot — отсутствие ключевых блоков |
| Несоответствие тёмной/светлой темы | скриншот (если тема меняется) |

## Шаг 4 — сформировать отчёт

После проверки всех страниц вывести краткий отчёт:

```
## Результаты проверки вёрстки

### ✅ Без замечаний
- login (desktop + mobile)

### ⚠️ Замечания
- dashboard (desktop): ...
- categories (mobile): ...

### ❌ Ошибки в консоли
- [page]: [message]
```

Если всё в порядке — сообщить `✅ Вёрстка проверена, критических проблем не обнаружено.`

## Правила

- Не вносить никаких изменений в код — только наблюдение.
- Не запускать dev-сервер самостоятельно — только проверять, что он запущен.
- Закрывать браузер после завершения всех проверок через `mcp__playwright__browser_close`.
- Скриншоты сохранять во временные файлы только если пользователь явно попросил.
